# Phase 2: Background SyncWorker, API Connectivity & Idempotency — Implementation Plan

## Goal
Fix double `/api` URL construction in `SyncWorker.kt`, replace hardcoded expense type IDs with dynamic resolution against backend active expense types, ensure transactions sync with a valid `expense_type_id`, improve transaction fingerprinting so identical bank references and amounts produce stable idempotency keys across different delivery timestamps, and preserve durable retry handling and offline queueing.

## Target Files
1. `android/app/src/main/java/com/moneytrack/app/sms/SmsTransaction.kt`:
   - Enhanced `Fingerprint.of()`:
     - When `reference` is present and valid, derive the fingerprint from normalized sender entity, bank reference ID, and amount (independent of delivery `timestampMs`).
     - Normalized telecom prefixes (e.g. `AD-HDFCBK` and `VM-HDFCBK` normalize to `HDFCBK`).
     - When `reference` is null, fall back to normalized sender entity, ISO date (or day bucket), and amount.
     - Added `ActiveExpenseType(val id: Int, val name: String, val category: String?)` data model.

2. `android/app/src/main/java/com/moneytrack/app/sms/SyncWorker.kt`:
   - **URL Construction**:
     - Implemented `buildEndpointUrl(backendUrl: String, endpoint: String): String`.
     - Normalizes `backendUrl` whether provided as `http://10.0.2.2:8000` or `http://10.0.2.2:8000/api` or with trailing slashes.
     - Prevents double `/api/api/expenses`.
   - **Dynamic Expense Type Resolution**:
     - Fetches active types from `${apiBase}/expense-types?archived=exclude` via `fetchActiveExpenseTypes(backendUrl: String)`.
     - Robust parsing via `parseExpenseTypesJson(jsonString: String)`.
     - Implemented `resolveExpenseTypeId(suggestion: String?, merchant: String?, activeTypes: List<ActiveExpenseType>): Int?`:
       - Match exact type name (case-insensitive).
       - Match type category.
       - Match category aliases (`Transport` -> `Travel`, `Groceries` -> `Food`, `Fuel` -> `Travel`, etc.).
       - Match partial/substring on type name.
       - Match merchant name against active type names.
       - Fall back to active type named/categorized as `Other` or `General`.
       - If still unmatched, fall back to the first available active type so the transaction can be safely synced and recorded with a valid `expense_type_id`.
       - Return `null` only if no active types exist on the backend.
   - **Idempotency Key Usage**:
     - Uses `record.id` as the `Idempotency-Key` request header.
     - Detects `X-Idempotent-Replay: true` (HTTP 200) and treats as successful sync without error or duplication.
   - **Retry & Error Handling**:
     - Preserves exponential backoff retry scheduling via `WorkManager`.
     - If network/backend is unreachable or returns 5xx, records failure and triggers retry.

3. `android/app/src/main/java/com/moneytrack/app/sms/SmsReceiver.kt`:
   - Updated `Fingerprint.of()` invocation to pass `parsed.transactionDate` so queue deduplication uses the enhanced durable fingerprint.

4. `android/app/src/test/java/com/moneytrack/app/sms/SyncWorkerTest.kt`:
   - Unit tests URL construction for `http://10.0.2.2:8000`, `http://10.0.2.2:8000/`, `http://10.0.2.2:8000/api`, and `http://10.0.2.2:8000/api/`.
   - Unit tests dynamic expense type resolution across exact match, category match, aliases, merchant match, and fallback.
   - Unit tests fingerprint stability across differing delivery timestamps and telecom prefixes.
   - Unit tests fingerprint differentiation for distinct bank references.
   - Unit tests idempotent replay header parsing.
