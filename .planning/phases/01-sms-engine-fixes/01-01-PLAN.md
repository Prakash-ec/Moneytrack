# Phase 1: SMS Native Engine & Parser Fixes — Implementation Plan

## Goal
Fix native Android SMS parsing, amount extraction (prioritizing debit over balance), merchant detection (body over bank sender), Indian date formats (textual months), category suggestions, receiver security permissions (`BROADCAST_SMS`), and remove unnecessary `READ_SMS` permission while preserving `RECEIVE_SMS`.

## Target Files
1. `android/app/src/main/AndroidManifest.xml`:
   - Add `android:permission="android.permission.BROADCAST_SMS"` to `SmsReceiver`.
   - Remove `<uses-permission android:name="android.permission.READ_SMS" />`.
   - Keep `android.permission.RECEIVE_SMS`, `android.permission.INTERNET`, `android.permission.POST_NOTIFICATIONS`.
2. `android/app/src/main/java/com/moneytrack/app/plugins/SmsPlugin.kt`:
   - Remove `READ_SMS` permission annotation and alias from runtime permission requests.
   - Retain `RECEIVE_SMS` and `POST_NOTIFICATIONS`.
3. `android/app/src/main/java/com/moneytrack/app/sms/SmsParser.kt`:
   - **Amount Extraction**:
     - Specifically identify and discard amounts linked to balance keywords (`avail bal`, `available balance`, `ac bal`, `bal:`, `bal is`).
     - Detect and prioritize debit-associated amounts (`debited by/for/with`, `spent`, `paid`, `plan name`).
     - Never pick an account balance over a transaction debit amount.
   - **Merchant Extraction**:
     - Parse in-body merchant names from `to VPA <handle>@<bank>`, `at <Merchant>`, `to <Merchant>`, `Info: <Merchant>`, `paid to <Merchant>`.
     - Strip trailing keywords (`on`, `ref`, `date`, `via`).
     - Fall back to bank sender ID only if no merchant is identified in the body.
   - **Date Formats**:
     - Support alphanumeric month formats: `dd-MMM-yy`, `dd-MMM-yyyy`, `ddMMMyy`, `ddMMMyyyy`, `dd MMM yyyy`, `dd-MM-yyyy`.
     - Standardize all dates to ISO `yyyy-MM-dd`.
   - **Category Suggestions**:
     - Improve suggestions for common Indian merchants (Swiggy/Zomato -> Food, Blinkit/Zepto -> Groceries, Uber/Ola/IRCTC -> Transport, Apollo/PharmEasy -> Health, Amazon/Flipkart -> Shopping, Jio/Airtel -> Mobile Recharge, Electricity/Bescom -> Utilities).
     - Keep suggestions as clean category names without hardcoding database IDs.
4. `android/app/src/test/java/com/moneytrack/app/sms/SmsParserTest.kt`:
   - Add synthetic tests for HDFC, SBI, ICICI, and Axis formats.
   - Add tests verifying debit amounts are extracted rather than available balances.
   - Add tests verifying body merchants take precedence over sender IDs.
   - Add tests for `28-OCT-26`, `28-Oct-2026`, `28Oct26`, and `28 Oct 2026`.
   - Verify all existing tests continue to pass.
